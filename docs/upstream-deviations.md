# Upstream deviations

Changes made on `work/scriptc-native` that diverge from upstream pyright, why they exist, and what an upstream merge should do with them.

| file/patch | what changed | why (scriptc fence) | upstream-merge note |
| --- | --- | --- | --- |
| `packages/pyright-internal/src/scriptcCompat/vscodeJsonrpc.ts` | New file: modern-TS reimplementation of the `vscode-jsonrpc` (+ `/node`, `/browser`) surface pyright imports — Disposable, Emitter/Event, CancellationToken(Source), ResponseError, ErrorCodes/LSPErrorCodes, RequestType*/NotificationType*/ProgressType factories, message reader/writer classes. LinkedMap replaced by a plain array-backed listener list. | The real package is CJS and fences ~15 scriptc errors (LinkedMap, RAL, message-buffer machinery). | Keep as a fork-local shim; do not merge upstream — upstream keeps the real dependency. |
| `packages/pyright-internal/src/scriptcCompat/vscodeLanguageserver.ts` | New file: shim for `vscode-languageserver` — re-exports `vscode-languageserver-types` + the jsonrpc shim, plus WorkDoneProgress/reporter objects; LSP-server-only names exist only so esbuild named imports resolve. | CJS LSP-server machinery is out of scope for the native typecheck CLI; ~8 scriptc errors. | Keep fork-local. |
| `packages/pyright-internal/src/scriptcCompat/vscodeLanguageserverProtocol.ts` | New file: shim for `vscode-languageserver-protocol` — ProtocolRequestType/NotificationType classes and the named request/notification objects with identical method strings. | CJS protocol package fences ~5 scriptc errors. | Keep fork-local. |
| `packages/pyright-internal/src/scriptcCompat/vscodeLanguageserverNode.ts` | New file: shim for `vscode-languageserver/node` + `/browser`; `createConnection` throws "not supported in native CLI". | Node LSP transport (sockets/ports) is never used by the typecheck CLI. | Keep fork-local. |
| `packages/pyright-internal/src/scriptcCompat/chokidar.ts` | New file: ~100-line `watch()` replacement backed by `node:fs.watch`, matching the `FSWatcher.on('all', cb)` / `close()` surface used by `chokidarFileWatcherProvider`. | chokidar pulls in fsevents handlers and CJS internals (~8 scriptc errors). | Keep fork-local; if upstream ever wants a lighter watch dep this can be proposed separately. |
| `packages/pyright-internal/src/scriptcCompat/sourceMapSupport.ts` | New file: `install()` no-op matching the `source-map-support` surface used by `common/asyncInitialization.ts`. | Source-map stack rewriting is meaningless for a compiled native binary; the real package + its `source-map` dep fence ~10 errors. | Keep fork-local. |
| `packages/pyright/package.json` `bundle:cli:flat` | Added `--banner:js` (createRequire + `__dirname` ESM shims so the flat bundle also runs under Node) and `--alias` flags redirecting `vscode-languageserver(-protocol, /node, /browser)`, `vscode-jsonrpc(/node, /browser)`, `chokidar`, `source-map-support`, and `jsonc-parser` (to its ESM build, fixing a UMD `require('./impl/*')` bundling gap) at the compat shims. | Aliases drop the CJS vscode-\* machinery from the flat bundle entirely; banner makes `node pyright-flat.js` runnable for parity checks. | Fork-local build script; no upstream impact. |
